      Help Guide — Purchase Return

      Purpose

      Purchase Return is the Procurement-side mirror of Sales Return: it sends goods back to a vendor and records the physical fact in the Stock Ledger. Like its Sales-side counterpart, it deliberately records no money at all — that's Debit Note's job.

      Business Process

      Pick the Posted GRN these goods were received on — not the Purchase Order or the informal dock-entry Goods Receipt, because the GRN is this project's own formal, numbered receiving record. Every line starts at a return quantity of zero. Posting writes one Stock Ledger entry per returned line — but only for a line whose warehouse currently holds enough of that item. If some of what was received has already been sold, issued, or transferred elsewhere, that line is skipped rather than posted anyway, and you'll be told which lines didn't go through.

      Real Industry Usage

      A single GRN can be defective in ways you discover gradually — three units this week, two more once someone tests them next month — so this module allows as many partial returns against one GRN as reality demands. A cumulative quantity guard stops you from returning more than the GRN actually recorded as received, the exact same discipline Sales Return applies to what was invoiced.

      Tips

      • If a post reports a skipped line, check where that stock actually went (Stock Ledger, filtered to the item) before assuming something is wrong — it usually means the goods were already used elsewhere.
      • Cancelling a Draft frees its quantities back up immediately for another return against the same GRN.
      • Pick the reason carefully — "Damaged on Receipt" and "Wrong Item Shipped by Vendor" usually belong in a vendor performance conversation, not just a stock adjustment.

      Common Mistakes

      • Expecting this module to reduce what you owe the vendor. It doesn't — raise a Debit Note for that.
      • Assuming a post always fully succeeds. It's genuinely possible for goods received weeks ago to no longer be sitting in that warehouse.
      • Trying to return more than the GRN recorded. The form blocks it and tells you exactly how much is still returnable.
      • Assuming a posted return can be edited or reversed. It can't — the Stock Ledger never allows an update or a delete, anywhere in this system.

      ERP Best Practices

      • Record the return the day the goods physically leave, not the day the vendor agrees to the debit note.
      • Track return reasons by vendor over time — a vendor with a rising damaged-on-receipt rate is a sourcing decision waiting to happen.
      • Reconcile Purchase Return against Debit Note regularly, the same way you'd reconcile Sales Return against Credit Note — a long-open return with no note behind it is money still sitting with the vendor.
